## 修复：情绪画面动效在真实浏览器中不可见
- 问题：`css/emotion-fx.css` 的 `@media (prefers-reduced-motion: reduce)` 把粒子与光晕全部 `display:none`。当用户系统/浏览器开启"减少动态效果"（Windows 常见）时，8 种情绪的氛围粒子全部消失，只剩背景图。
- 修复：
  - 保留 `animation: none`（无动画，符合无障碍）。
  - 去掉 `display:none`，改为给每种粒子显式赋静态可见 opacity / transform，确保减少动态效果模式下情绪视觉仍在。
  - 提高 `.fx-ambience` 大环境光晕的呼吸透明度（0.16→0.30，峰值 0.26→0.48）。
  - 孤独月亮从 `top:5% right:2%` 下移到 `top:15% right:5%`，避免被主程序顶部导航栏盖住；月亮尺寸/光晕略增强。
- 验证：用 Chrome 原生无头截图测试（`--headless --screenshot`），复用真实 `emotion-fx.css` 与真实注入逻辑。结果：正常模式与减少动态效果模式均能看到月亮+暗角+光晕，修复前 reduce 模式几乎全黑。
- 截图证据：`F:/新建文件夹 (3)/_fx_gudu.png`（正常）、`_fx_gudu_reduce.png`（减少动态效果）。
- 校验：`node --check js/main.js` OK。
- 全面无头截图验证（真实 CSS + 真实注入逻辑 + 模拟顶部栏/面板）：
  - 基准（无粒子）：8.6 KB
  - 正常模式：anxin 26K / benshang 33K / qidai 42K / gudu 63K / kongju 63K（均显著高于基准，粒子已渲染）
  - 减少动态效果模式：anxin 44K / benshang 37K / qidai 63K / gudu 81K / kongju 89K（修复后同样显著高于基准，粒子不再被隐藏）
  - 修复前 reduce 模式仅约 27 KB（接近纯背景），证明旧规则确实把所有粒子 `display:none` 了。

## 2026-09-02 傍晚 —— 悲伤：细雨贯穿所有页面

用户反馈：悲伤情绪的画面动效没有贯穿点击情绪卡片后的所有页面。

根因：
- 之前悲伤的「细雨」写在 `.emotion-fx` 背景层（`z-index:-1`），被中央内容卡片盖住，几乎看不见。

修复：
- `F:/新建文件夹 (3)/zizaoji4_final_xuanxuan_audio_button/zizaoji4_final_xuanxuan_audio_button/css/emotion-fx.css`
  - 新增 `.sad-rain`：固定全屏 canvas，`z-index:5`（在页面内容之上），`pointer-events:none`，淡入淡出。
  - 在 `prefers-reduced-motion: reduce` 下隐藏雨 canvas（雨是纯动效，静态无意义；仍保留底部墨晕作为悲伤视觉）。
- `F:/新建文件夹 (3)/zizaoji4_final_xuanxuan_audio_button/zizaoji4_final_xuanxuan_audio_button/js/main.js`
  - 新增 `SadRain` 全局 canvas 雨滴引擎：挂在 `#app` 根，一次创建，切换页面不销毁。
  - 在 `applyEmotionBackground()` 中：情绪为 `benshang` 时 `SadRain.show()`，否则 `SadRain.hide()`。
  - 因为 `applyEmotionBackground` 在每次 `navigateTo()` 调用，全局雨 canvas 会在悲伤情绪的任意页面持续运行，自然贯穿所有页面。
  - 提高雨滴密度（约 32~52 滴）与透明度（0.22~0.52），让雨更明显但仍不挡文字。
